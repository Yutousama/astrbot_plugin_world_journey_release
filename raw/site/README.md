# 网页部分

三个单文件页面，**没有构建步骤、没有依赖、没有后端**。双击就能看，扔到任何静态托管也能用。

| 文件 | 是什么 | 给别人用吗 |
|---|---|---|
| `index.html` | 落地页。介绍 + 怎么装 + 碰面说明 | 是，这是门面 |
| `meet-setup.html` | 碰面配置助手。填地址、生成身份、测连通 | **是，可以单独发这一个文件** |
| `admin.html` | 运维面板。看今天多少人、有没有超预算 | 不，你自己用 |

## 本地看

直接双击 `index.html` 就行。要连着看三个（比如从落地页点进配置助手），起个静态服务更顺：

```bash
cd site
python -m http.server 8788
# 或者 npx serve .
```

然后开 `http://127.0.0.1:8788/`。

## 配置助手为什么值得单独发

`meet-setup.html` 不依赖另外两个文件，**可以只把这一个发给别人**。它解决的是三个真实问题：

1. **不知道地址填什么** —— 它会把「实际会请求什么」实时显示出来。填 `xxx.com` 显示 `xxx.com/sight`，填 `xxx.com/sight` 也不会变成 `/sight/sight`
2. **不知道 uid 是什么** —— 现在那是本地一个文件（`meet-uid.txt`），用户根本看不见。这里能生成一个、能存成文件，换电脑时填回去还是同一只鱼
3. **填完没反应，不知道是坏了还是没人** —— 点「测一下」直接打服务端，通了会说「这一带现在没人（这是正常的）」，不通会分情况告诉你 404 是路径错、500 是表没建、连不上是地址或跨域

**它只做只读探测**，不发上报 —— 不会占用服务器配额，也不会在别人那儿凭空多出一只鱼。

## 运维面板

`admin.html` 需要服务端配了 `ADMIN_KEY`（见 `cloud/sight-cf/README.md`）。不配的话 `/admin/*` 整条路 404，页面连不上，但碰面功能一点不受影响。

打开先显示**示例数据**，填地址 + 密钥点「连上」才换成真实数据。标签会从「示例数据」变成「实时数据」。

密钥存在浏览器 localStorage 里，只在这台机器上。清浏览器数据就没了，重填一次即可。

**它只读。** 封禁和清理走 `wrangler d1 execute`，网页上不留写入口。

## 发布

两种都行：

**WorkBuddy 的「发布为应用」** —— 把这个目录发成在线链接，改完重新发布。

**Cloudflare Pages** —— 拖整个目录上去，免费、自带 HTTPS、跟碰面服务在同一个账号下。

发布前记得改 `index.html` 里的 GitHub/npm 链接（现在没写死，只指向本地两个页面）。

## 改的时候注意

- **样式是内联的**，三份各自独立。改了配色要三个文件一起改，别只改一个
- 配色跟扩展的 WebUI 是同一套（`--jr-*` 那组变量的值）：暖米白 `#faf5ee`、赭橙 `#c06a35`，深色模式一套对应的
- `meet-setup.html` 的 `endpointOf()` 必须和 `src/meet.ts` 里的**逐字一致**，改一边记得改另一边 —— 两边拼得不一样，就会出现「助手说通了、扩展连不上」
